# tech-blocks: technical audit of VB-added and VB-changed blocks and block entities

## Summary
- 8 findings: **farm 2** (TBLK-101, TBLK-102), **gameplay 6** (TBLK-103, 104, 201, 301, 302, 303). Engine drift: 6 entries. TBLK-202 and TBLK-351 are farm, TBLK-203 and TBLK-352 are gameplay, and TBLK-151 and TBLK-152 are minor: TBLK-151 is fixed by TBLK-102, and TBLK-152 has no visible effect.
- Effective behaviour checked = VB 1.2.2 (`<vanillabackport-1.2.2>`) plus the add-on (`src/main`). Native = 26.2 (`<mc-26.2>`), or 26.3-pre-1 (`<mc-26.3-pre-1>`) for the Wilderness Bound blocks (poplar set, red shrub, shelf mushroom, straw bed).
- Covered for every block in scope:
  - random-tick conditions and chances, and the order of random calls
  - scheduled-tick and block-entity intervals
  - signal and comparator formulas, neighbour/shape updates, and observer-visible state changes
  - piston reaction and whether block entities can be moved
  - hoppers and dispensers, bone meal, shearing/scraping/waxing (with game events and level events), sculk frequencies
  - fluids, fire values, hardness/resistance/tool tags
  - the families: copper (incl. the oxidation neighbour formula), pale garden and flora, sulfur and geysers, dried ghast, Wilderness Bound
- First-round fixes re-verified as correct: COPPER-03/06/08/09/10/11/12/13, GARDEN-01/05/14/17/18/19, FLORA-01/04, SULFUR-21/22/23/24/25/26, GHAST-21/24, WILD-17. Fixes that are incomplete or have side effects:
  - FLORA-15 → TBLK-201
  - COPPER-09 → TBLK-102
  - SULFUR-31 → TBLK-301
  - SULFUR-13 → TBLK-302
  - WILD-24 → TBLK-303, TBLK-351
- Not checkable here: nothing ran in-game. Every result comes from reading the code, and the RNG-order claims come from static call order. Second-round work in `impl/p2-*` was ignored.

### TBLK-101  Waxed lightning rods count as unaffected copper and stop nearby copper from oxidising
- severity: farm
- vb: `src-vb/com/blackgear/vanillabackport/core/mixin/common/weathering_lightning_rods/LightningRodBlockMixin.java:31-51`: `@Mixin({LightningRodBlock.class}) public class LightningRodBlockMixin extends Block implements WeatheringCopper, BlockExtension { ... public WeatherState getAge() { return WeatherState.UNAFFECTED; } }`. The four waxed rods are plain `LightningRodBlock`s: `src-vb/.../registries/blocks/ModBlocks.java:453-464`: `"waxed_lightning_rod", LightningRodBlock::new, ...` (same for `waxed_exposed_`, `waxed_weathered_`, `waxed_oxidized_`). Only `WeatheringLightningRodBlock` overrides `getAge`. The add-on handles this for lightning (`CopperLightning.isWeatheringCopper`: `block instanceof WeatheringCopper && !isWaxed(block)`), but not for oxidation.
- native: `src-mc/net/minecraft/world/level/block/LightningRodBlock.java:26`: `public class LightningRodBlock extends RodBlock implements SimpleWaterloggedBlock` (no ChangeOverTimeBlock); waxed rods are `(var0, p) -> new LightningRodBlock(p)` (`Blocks.java:5307`). `ChangeOverTimeBlock.java:36-48`: `if (!blockPos.equals(pos) && level.getBlockState(blockPos).getBlock() instanceof ChangeOverTimeBlock<?> neighborBlock) { ... if (foundAge < ownAge) return Optional.empty(); if (foundAge > ownAge) olderCount++; else sameAgeCount++; }`
- difference: In VB every waxed rod, whatever its colour, is an age-0 `ChangeOverTimeBlock` neighbour. Natively waxed rods are ignored. Within Manhattan distance 4 of a waxed rod, exposed, weathered and unaffected-but-not-yet copper (any vanilla or VB weathering copper of age ≥ 1) returns `Optional.empty()` and **never oxidises again**. Unaffected copper gets one extra same-age neighbour, so its chance drops. Example: a lone copper block beside one waxed rod has native per-roll chance `(0+1)/(0+0+1)`² × 0.75 = 0.75; VB has `(1/2)`² × 0.75 = 0.1875 (4× slower). An exposed copper block beside it goes from 1.0 to 0. This affects copper roofs and oxidation farms with waxed rods (a common decoration). Other mods' `LightningRodBlock` subclasses are counted too.
- fix_kind: mixin-mc (interface `net.minecraft.world.level.block.ChangeOverTimeBlock`, default method `getNextState`)
- fix: an interface mixin `@Mixin(ChangeOverTimeBlock.class) interface ChangeOverTimeNeighbourMixin`, with `@WrapOperation(method = "getNextState", at = @At(value = "INVOKE", target = "Lnet/minecraft/world/level/block/state/BlockState;getBlock()Lnet/minecraft/world/level/block/Block;"))` and a `private static` handler: `Block b = original.call(state); return (b instanceof LightningRodBlock && !(b instanceof WeatheringLightningRodBlock) && b != Blocks.LIGHTNING_ROD) ? Blocks.AIR : b;`. This hides only waxed and foreign plain rods from the scan, and the plain unaffected rod still counts as age 0, as native `WeatheringLightningRodBlock(UNAFFECTED)` does. Java 21 allows private interface handlers, and Mixin 0.8+ supports injectors into interface default methods. If that is rejected at load, apply the same `@WrapOperation` through a copy of `getNextState` called from each weathering block's `randomTick` (VB's 6 weathering classes, the rod mixin and vanilla `WeatheringCopper*` classes).
- config_gate: `hasWeatheringLightningRods` (the waxed rods exist either way, so it's safer ungated)
